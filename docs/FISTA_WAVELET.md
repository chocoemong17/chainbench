# Noisy image restoration with actual Haar shrinkage

This development workflow runs the ISTA/FISTA subset of Beck–Teboulle (2009),
Section 5.2 / Figure 4. It follows the published noisy-image **protocol with a
new, declared noise draw**. It does not claim to recover the original noise,
Figure 4 pixels, or its reported endpoint values.

```sh
python -m chainbench reproduce fista-wavelet --lang ko --output wavelet.html
python -m chainbench reproduce fista-wavelet --format json --output wavelet.json
python -m chainbench reproduce fista-wavelet --seed 1 --output seed-1.html
python -m chainbench reproduce fista-wavelet --steps 10 --output preview.html
```

The default is 200 updates and PCG64 seed 0. Budgets are integers 1–200; seeds
are integers 0–2³²−1. Reduced budgets are visibly labelled previews. `--seed`
is accepted only for this reproduction; other commands reject it rather than
silently ignore it. Output overwrite still requires `--force`.

The self-contained page includes clean/observed images, synchronized stored
reconstructions, coefficient magnitudes, a three-stage Haar layout, three actual
first-update coefficients, four complete curves and downloadable numeric evidence.
Keyboard selection and all snapshots work offline; the native gallery and curves
remain available without JavaScript. Full arrays make this page about 30 MB,
depending on seed and budget. The compact guided tour omits this larger page;
the newer [optional extended tour](OFFLINE_TOUR.md#optional-extended-path) includes
the default 200-update, seed-0 record and links it to the noiseless experiment.

## Source and exact scope

Primary source: [Beck and Teboulle, *A Fast Iterative Shrinkage-Thresholding
Algorithm for Linear Inverse Problems*](https://www.tau.ac.il/~becka/FISTA.pdf).
Section 5 (printed p.197 / PDF p.15) specifies a three-stage Haar transform,
9×9 Gaussian blur with standard deviation 4, reflexive boundaries and additive
white Gaussian noise with standard deviation 10⁻³. Section 5.2 (printed p.199 /
PDF p.17) gives the 256×256 simple Regularization Tools image, λ=10⁻⁴ and the
100/200-update comparison in Figure 4 (printed p.200 / PDF p.18).

The paper supplies neither the exact noise realization nor a toolbox version hash
or every Haar sign/layout convention. The JSON explicitly retains these choices.
MTWIST and Cameraman are outside this workflow. The separate
[noiseless Figure 5 export](FISTA_DEBLURRING.md) remains 64×64, λ=0 and 10,000 updates.
The fixed eight-check suite is unchanged.

The synthetic image is generated by the attributed image-only port of Hansen's
Regularization Tools 4.1 (March 2008) in `_regutools_image.py`. The original
copyright and permission notice is retained there, in JSON and in the page.
The [Netlib archive](https://www.netlib.org/numeralgo/na4-matlab7.tgz) SHA-256 is
`07a8e8844a5593fc8ba739428b7637391342d8467be989bfb08681ee65f24b97`;
its `blur.m` SHA-256 is
`6ab03d347375aab26c847d924ff00cd1936d5324be53adcf4409a910f6890ac5`.
The paper does not identify that archive version as its precise input.

## Coordinates, operators and scaling

Let W denote orthonormal Haar synthesis and R the separable blur. The objective is

    b = R u_clean + noise
    F(c) = ||R W c - b||² + lambda ||c||_1
    c0 = W^T b, y0 = c0, t0 = 1
    gradient(c) = 2 W^T R^T (R W c - b)

This is a **full** squared loss. There is no factor ½. Blur uses a normalized
one-dimensional kernel `exp(-j²/32)`, j=−4,…,4, in both directions. The symmetric
extension repeats the edge: index −1 maps to 0; index n maps to n−1. This R is
self-adjoint, nonnegative and doubly stochastic. Hence its spectral norm is 1
(the constant image attains it), and orthonormal W gives L=2. Step size is ½,
so the shrinkage threshold is λ/L=0.00005.

Three separable Haar stages use adjacent even/odd pairs with average
`(a+b)/sqrt(2)` and detail `(a-b)/sqrt(2)`. Each stage transforms horizontal then
vertical pairs, recursing **only in the top-left LL block**. Each level stores
horizontal details at top-right, vertical details at bottom-left and both at
bottom-right. The deepest LL block is 32×32. Synthesis applies the transposed
stages in reverse order. Every coefficient, including LL, is penalized.

Both methods reuse the package's existing proximal iteration stream. ISTA uses
`soft(c - gradient(c)/L, lambda/L)`. Fixed-L FISTA evaluates that operation at y,
then updates `t_next=(1+sqrt(1+4t²))/2` and
`y_next=c_next+(t-1)/t_next*(c_next-c)`. The first updates coincide. A clean
reference image is used only for RMSE; it does not enter the gradient or prox.

The noise is `Generator(PCG64(seed)).normal(0, .001, (256,256))`. Exact noise values
and environment are retained because a seed alone is not a cross-version array
guarantee. Changing the seed makes another declared example, not a representative
sample. No noise draws are filtered by their outcomes.

## What the evidence means

Every row, including k=0, records F, squared residual, λ||c||₁, clean-reference
image RMSE and the exact count of zero coefficients. Stored snapshots are
0, 1, 10, 100, 200 when within the budget, plus its last iterate. Each snapshot
retains the full image and coefficients, hashes, unclipped image range and the
proximal gradient mapping norm `||L[c-soft(c-gradient(c)/L,lambda/L)]||₂`.

The optimum is unknown and `f_star` is explicitly null: F is **not** an
optimality gap. The mapping norm is a stationarity observation. Neither it nor
RMSE is a theorem certificate. One noise draw does not establish a method ranking.

### Development addition: a dual lower bound at each saved point

[Kim, Koh, Lustig, Boyd and Gorinevsky (2007)](https://stanford.edu/~boyd/papers/l1_ls.html),
Section III-B, Eqs. (10) and (12), printed p.609 / PDF p.4, gives a dual for the
**full** squared loss. With A=RW and r=Ac−b:

    D(nu) = -||nu||²/4 - <b,nu>, subject to ||A^T nu||_infinity <= lambda
    D(nu) <= F* <= F(c), so 0 <= F(c)-F* <= F(c)-D(nu).

The candidate used here is independently derived from that constraint:
`nu=2*s*r`, `h=||2*A^T*r||_infinity`,
`s=(1-1e-12)*min(1,lambda/h)`; h=0 uses s=1−1e−12. This caps the scale
and introduces a floating-point safety margin. It is **not** a literal
transcription of Eq. (11): that printed display has ambiguous dimensions/indexing
in its residual-adjoint term, and does not print our cap or safety factor.
The implementation uses the explicitly dimensionally consistent Aᵀ(Ac−b).
It checks Aᵀnu again and fails if nonfinite or numerically infeasible.

Each snapshot's `dual_bound` retains the scale, both adjoint infinity norms,
feasibility margin, the two dual-objective terms, D, F and F−D. All arrays
needed to reconstruct nu are already retained; no second copy is necessary.
The identity

    F-D = ||r-nu/2||² + lambda||c||_1 + <A^T nu,c>

is independently recomputed, including its raw floating residual. In exact
arithmetic both right-hand terms are nonnegative for a feasible nu. This is a
numerical objective bracket, not an interval-arithmetic certificate, the exact
unknown gap, or a bound on clean-image RMSE. No clean image enters its calculation.
The scale affects only the diagnostic. Every existing iterate and row is retained.

The page synchronizes two D-to-F intervals with the existing snapshot selector.
Both methods share a linear horizontal scale at a selected k; that scale changes
with k and its endpoints are printed. The optimum is not assigned a plotted
position. The native table preserves all unfiltered values, including a declining
D, and works without JavaScript. Old records without this optional addition
remain readable; current installed exports are required to include it.

This applies a public dual bound to the existing Beck–Teboulle rerun. It does
not implement Kim et al.'s interior-point method or reproduce their MRI data.

Image display alone clips to [0,1] and rounds to 8-bit grayscale. Coefficient
images show `log(1+abs(c))/log(1+M)` with the same M across every stored coefficient
array and both methods. This omits coefficient sign and emphasizes small values;
M is displayed. Numerical optimization, metrics and JSON are never clipped.

The first-update table selects the smallest |z|, largest |z| and |z| closest to
the threshold, breaking ties with the first row-major index. This selection is
an illustration of shrinkage rather than a sample claiming coverage.

## Validation

Tests check inverse/adjoint/energy identities, direct dyadic block coefficients,
the operator against a dense reflected blur, the gradient against a Kronecker
operator and finite differences, exact loss/threshold scaling, image generation
against scalar one-based indexing at both 64 and 256, exported arrays and hashes,
CLI scope errors and deliberate evidence corruptions.

`scripts/smoke_wavelet.py` independently constructs Haar analysis/synthesis from
dyadic block bases and blur from explicitly reflected indices, without importing
ChainBench. It recomputes every ISTA/FISTA update and row, all saved arrays and
stationarity metrics. Numeric comparison is rtol=2e−9, atol=2e−11; saved image and
coefficient arrays use atol=1e−9 because different summation orders accumulate
near-zero differences through 200 accelerated steps (maximum coefficient
difference about 4.9e−10 over declared seeds 0, 1, 2; maximum pixel difference
about 1.3e−10). That absolute tolerance is 50,000 times below the shrinkage
threshold, not a claim of exact bitwise recurrence equivalence.
Hashes are checked exactly against the saved arrays, not against a numerically
different reference implementation. Corruption tests demonstrate rejection.

Dual-bound tests also use an identity-design LASSO with a closed-form optimum
and an explicit 64×64 dense blurred-Haar operator. The independent export check
reconstructs the candidate from saved arrays with separate block-basis Haar and
indexed blur implementations. Wrong signs, half-loss scaling, candidate scaling,
infeasibility, missing data and NaN are rejected. Browser checks compare the
interval's actual SVG coordinates and native table values to every saved record.

The clean-install workflow exercises the full default command and independently
validates its JSON and HTML for both distributions. The browser workflow checks
desktop/mobile, every stored image and coefficient pixel, curve metadata,
selection, keyboard, language, downloads and no-script access. Configuring these
checks is not evidence they have run on a new remote commit; consult that PR's CI.

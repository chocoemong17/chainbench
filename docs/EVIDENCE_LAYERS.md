# Evidence layers: what one plot can and cannot say

A single attractive trajectory is useful for intuition but weak evidence of generality. ChainBench v0.5.0 separates four different questions instead of mixing them together.

## 1. Literature claim

This layer states the public theorem, specialization or empirical quantity being discussed, together with assumptions. It is mathematical context from the cited source, not something established by a screenshot.

## 2. Canonical illustration

A small deterministic problem makes the mechanism visible. These plots are generated by ChainBench, not copied from the original paper unless explicitly stated otherwise. A canonical illustration is intentionally chosen for clarity and is **not** presented as representative sampling.

## 3. Seeded multi-instance stress

`chainbench stress <topic>` repeats the same paper-linked measurement on many reproducible synthetic instances. Seeds and instance parameters are retained in JSON. This answers a different question: "does the implementation continue to behave consistently across the sampled family?"

Finite sampling still does not prove the theorem. Heavy-ball's 8% line remains an empirical project regression tolerance. ISTA/FISTA remains descriptive with no universal pass/fail threshold.

## 4. Published tight case

Only when public literature supplies both an upper bound and a matching extremal construction can ChainBench label a case as tight. The current explicit example is the Drori--Teboulle constant-step GD construction documented in `GD_TIGHT_CASE.md`.

A difficult random sample is not a certified worst case.

## Geometry is a fifth view, not a fifth proof

`chainbench landscape` places the **same numerical run** on a contour map, a 3D objective surface and a convergence chart. It is designed to explain zig-zagging, momentum, conjugate directions and implicit steps. The 2D problem is deliberately chosen for visual clarity, so it belongs to the illustration layer rather than the stress layer.

## Recommended reading order

1. Read the question and assumptions in `chainbench learn`.
2. Inspect the canonical plot and geometry.
3. Run seeded stress if you want breadth beyond one example.
4. Inspect a tight case only when literature justifies the word "tight".
5. Use JSON/CSV/replay when you need auditable numerical evidence rather than presentation.
